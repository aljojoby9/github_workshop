2. What is Git?

Git is a version control system used to track changes in files and projects.

Git runs on your computer and keeps a history of changes made to your project.

Example

Version 1
    ↓
Version 2
    ↓
Version 3
    ↓
Version 4

3. What is GitHub?

GitHub is an online platform where Git repositories can be stored and shared.

GitHub also provides features for collaboration, code review, issue tracking and project management.

Git vs GitHub

  • Git: Version control system.
  • GitHub: Online platform for hosting and collaborating on Git repositories.

4. What is Version Control?

Version control means keeping track of the changes made to a project over time.

Instead of creating multiple copies of a project, Git keeps a history of the different versions.

Without Git

website-final
website-final-new
website-final-new2
website-final-latest

With Git

Project
   |
   ├── Commit 1
   ├── Commit 2
   ├── Commit 3
   └── Commit 4

5. Important Git Concepts

Repository

A repository is a project that is being tracked by Git.

Commit

A commit is a saved snapshot of changes in the project.

Staging

Staging means selecting the changes that you want to include in your next commit.

Branch

A branch is a separate line of development. It allows us to work on a feature without directly changing the main branch.

Remote

A remote is a repository stored somewhere outside your local computer, such as GitHub.

Pull Request

A Pull Request is a request to review and merge changes from one branch into another.

Fork

A fork is your own copy of another GitHub repository.

Issue

Issues can be used to track bugs, tasks and feature requests.

Working Directory

The files that you are currently working on.

Staging Area

The changes that you have selected for your next commit.

Local Repository

The Git history stored on your computer.

GitHub Repository

The remote copy of your repository stored on GitHub.

7. Basic Git Commands

Click Copy to copy any command.

Check Git Version

git --version

Checks whether Git is installed and displays its version.

Initialize a Repository

git init

Initializes Git in the current project folder.

Clone a Repository

git clone <repository-url>

Downloads an existing GitHub repository to your computer.

Check Repository Status

git status

Shows the current status of files and changes.

Stage Changes

git add .

Stages all changed files for the next commit.

Commit Changes

git commit -m "Update project"

Saves the staged changes as a commit.

View Commit History

git log --oneline

Push Changes

git push

Uploads local commits to GitHub.

Pull Changes

git pull

Downloads the latest changes from GitHub.

View Branches

git branch

Create a New Branch

git switch -c feature-name

Switch Branch

git switch main

View Changes

git diff

View Remote Repository

git remote -v

8. Basic Git Workflow

The basic workflow is: 

Make changes
     ↓
git status
     ↓
git add .
     ↓
git commit -m "message"
     ↓
git push

Example

git status
git add .
git commit -m "Update README"
git push

9. Branches

Branches allow developers to work on different features without directly changing the main branch. 

              main
                |
        ----------------
        |              |
        ↓              ↓
   login-feature   payment-feature
        |              |
        ↓              ↓
      Work           Work

Create a Branch

git switch -c login-feature

Work on the Branch

git add .
git commit -m "Add login feature"
git push -u origin login-feature

10. Pull Requests

A Pull Request allows developers to propose changes and have them reviewed before merging them into another branch.

Typical Process

Create branch
     ↓
Make changes
     ↓
Commit changes
     ↓
Push branch
     ↓
Create Pull Request
     ↓
Code Review
     ↓
Merge

Pull Requests are commonly used when working with a team.

11. GitHub Features

  • Repositories: Store projects.
  • Issues: Track bugs and tasks.
  • Pull Requests: Review and merge changes.
  • Branches: Manage different lines of development.
  • Actions: Automate development workflows.
  • README: Document a project.
  • Forks: Create your own copy of a repository.
